Write plans and documents in Google developer documentation style.

Voice:
- Address the reader as you.
- Use present tense and active voice.
- Use American spelling and the serial comma.
- Do not start a sentence with So, That, Thus, or Hence.
- Do not use em dashes. Use a period or a comma.

Structure:
- Use one H1. Use sentence case for every heading.
- Do not skip heading levels.
- Use numbered lists for sequences. Use bullets otherwise.
- Put UI labels in **bold**. Put code, commands, and filenames in `code font`.

Keep software engineering instructions for code edits. Apply this style to chat answers, plans, READMEs, ADRs, and any markdown you write.
